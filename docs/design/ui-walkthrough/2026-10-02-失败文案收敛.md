### 三条**故意共用一句**的地方 —— 这是产品决定，请重点看

1. **练习记录**：列表失败与详情失败共用一句。我认为学员看到的都是「练习记录」这一件事，
   分成两句会让同一屏的两种失败读起来像两个功能坏了。
2. **每日一读**：加载 / 播放 / 跟读提交共用一句。具体是哪一步没说清**由屏幕的相位去说**
   （它本来就在说），这句话负责的是「学员能做什么」。
3. **话题建议**：今天的卡 / 打卡 / 忽略共用一句。忽略失败与打卡失败对学员是同一件事
   （这一下没成，再试一次）。

⇒ 若你要求「每一步各说各的」，这是一次**扩表**（每个失败点一行），不是重写。

## 三、其余四条规矩（都在代码注释里写明了）

1. **服务端自己给的话原样转达**：`APIError.backend(code, message)` 的 `message` 非空时直接用它。
   这条是既有三个 seam（drill / accountAuth / createPractice）本来就有的规矩，
   我第一版漏了，被 `reviewMiddlewareSurfacesCorpusAcceptFailure` 当场抓住。
2. **`AudioEngineError` 单独放行**：它是本仓唯一一个「错误类型自己承载用户文案」的类型。
   放行写在那个类型上（新增 `userFacingMessage`，与既有的 `telemetryDetail` 成对），
   不是散在七个 catch 里 —— 这样「哪一份给谁」有一个可读的出处。
3. **`appBootstrapErrorMessage` 的形状是错的，已改**：它以前是「只要是 `LocalizedError` 就信它」，
   而 `ClientASRError` 的 `errorDescription` 是 `Client ASR engine error: …` —— 那条假设站不住。
4. **两条测试改了**：`appLaunchMiddlewareSurfacesBootstrapFailure`（此前钉「消息 == `errorDescription`」，
   钉的正是错的那一半）改成钉反面；`reviewMiddlewareSurfacesCorpusAcceptFailure` 没改，是它抓出了我的漏。
