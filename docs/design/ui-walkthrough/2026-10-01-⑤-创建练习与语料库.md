## 0. 这两屏的截图是怎么来的（先读这一节）

**屏幕背后的数据是样例，不是真机联调。** 本机没有在跑的后端（`127.0.0.1:8080` 无响应），
所以截图走的是 `FW_SCREEN=<name>` 一条 DEBUG 通道（`DebugScreenPreview`）：

- 它换掉的是**数据面**（`CorpusClientProtocol` 的替身），不是往 state 里塞结果 ——
  所以 app 走的仍是 `.appear → 中间件 → 客户端 → 投影 → 视图` 那条真路；
- 创建练习那一屏**没有**替身（它不需要数据）。「开始练习」真的会去打后端，只是没后端可打。

⇒ 「联调通了没有」这件事**这两张图证明不了**，别把它们当端到端证据。

## 1. 对照稿子逐项看

### 1.1 创建练习弹层（屏 11）

| 稿子要求 | 截图里 | ✅/❌ |
|---|---|---|
| 底部弹层、非全屏 | 占到屏幕下方约八成，可下拉关闭 | |
| 三种输入并列：一句话描述 / 粘贴素材 / 预置场景 | 三枚并列胶囊 | |
| 默认停在「一句话描述」 | 左侧那枚是选中态（品牌色实底） | |
| 输入框问句「今天想练什么？」 | 有 | |
| 隐私声明**常驻**（不是弹窗） | 盾牌图标 ＋「素材仅用于生成练习，不用于训练」 | |
| 会话时长两项并列、**不做视觉降级** | 标准 / 迷你，两项都有「N 回合 · 约 N 分钟」 | |
| 主按钮「开始练习」 | 有；文本不足时置灰 | |

要确认的（我单方面定的，稿子没写）：

1. **文本两路共用一份草稿**：从「一句话描述」切到「粘贴素材」，写下的字不丢。稿子没规定，
   我按「同一段文字、只是送达时的 `kind` 不同」处理。
2. **两种文本输入共用同一条下限「≥10 字」**：稿子只给「一句话描述」写了 ≥10 字，
   粘贴那一路只写了上限 2000。我给粘贴也补了同一条下限 —— 粘 3 个字同样不够生成一段练习。
3. **超过 2000 字不截断**，而是把「超出 N 字」说出来并挡住提交。截断更省事，但粘贴 3000 字的人
   会以为全进去了。
4. **「开始练习」之后是进房间、不是立刻开会话**：会话在房间里点说话键时才建
   （与既有的「没有任何自动开始」一致）。稿子的 2 次点击审计数到「进房间」为止。

### 1.2 语料库（屏 08）

| 稿子要求 | 截图里 | ✅/❌ |
|---|---|---|
| 顶部「N 个话术块」 | 有 | |
| 场景 chips：Standup / Design Review / 1:1 / 面试 … | 有（横滑） | |

| 卡片三段式：中文意图（加粗）/ 英文块（强调色）/ 对比锚点（可折叠） | 有；锚点默认展开、点标题折叠 | |
| 右上角状态灯三态 | 三张卡分别是 ● 绿 / ◐ 黄 / ○ 灰 | |
| 已自动化显示「开会用上过 N 次」 | 第一张卡有（绿字） | |
| 搜索 ＋ 收藏筛选 | 搜索框 ＋「收藏」胶囊 | |
| 空态：三个形态纵向排成一条进度轴 ＋ 主按钮 | `corpusEmpty.png` | |
| 右滑快捷操作 / 单条删除 | 右滑出现「收藏 / 删除」 | |

要确认的（我单方面定的）：

1. **中文标签是我补的**：稿子只给了 Standup / Design Review / 1:1 / 面试、表达反对 / 请求澄清 /
   汇报进度 / 推迟排期 这八个，其余七个（闲聊 / 提出建议 / 表示同意 / 表示不同意 / 提出问题 /
   总结要点 / 承诺跟进）按同一口吻补齐。**这七条要你过一眼。**
2. **筛选是本地筛已加载的那一页**，与既有的搜索同一条路。服务端其实支持 `scene` / `func` 参数
   （`internal/corpus/http.go:106-115`），但客户端没走 —— 于是「列表没取完」时筛出来的结果并不完整。
   这一条我在标题旁加了一句「（还有更多没加载）」把它说出来，但**根子上是没接通**，
   已记进 `ui-rebuild-plan.md`。
3. **筛选是「取值相等」不是搜索式的「包含」**：拿搜索那套 `contains` 复用的话，
   `review` 会把别的标签一起带走。
4. **计数在筛选时写成分数**「筛出 3 / 24」：只报一个数的话，学员分不清「库里就这么多」
   与「筛完剩这么多」。
5. **认不出的标签不画那枚签**（与 F2 状态灯同一条纪律）。

### 1.3 全局（这一票顺带改的）

- **深色是默认外观**：`FluentWorkHostApp` 加了 `.preferredColorScheme(.dark)`。理由是稿子自述
  「浅色主题未出稿；深色为默认」，而令牌只在深色底上成立。**这是截图抓出来的**：
  不设它的时候，搜索框的占位文字走系统浅色 secondary，在深色令牌底上几乎看不见。
- **语料库的「刷新」工具栏按钮删掉了**：稿子 屏 08 没有工具栏。刷新改成下拉手势（系统自带）。

## 2. 四种状态各一遍
