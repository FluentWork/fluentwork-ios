## 2. 我单方面做的决定（请你确认或推翻）

1. **不做任何点了没反应的东西**。稿子的四组里，账号背后没有登录链路（iOS 只有游客身份）、
   通知背后没有推送、提示音本身还不存在、AI 语速要动音频链路 —— 这些**不是用一排禁用的开关
   占位**，而是先不出现，并在这里逐条写明。禁用开关会让人以为「等一等就能用」，
   而它们缺的不是时间。
2. **确认文案里不写数字**。稿子要求写出「衍生的 **N** 个话术块也会一并删除」，而那个 N
   **删之前拿不到**：服务端只在删除的回包里给（`DeleteAccountDataResponse.cascaded`），
   客户端也数不出来（语料库是游标分页的，只有 `nextCursor`，没有 total）。
   用已加载那一页的条数当 N 会**少报**这次损失的规模 —— 而少报一个不可逆操作的后果
   是最不该犯的那类错。所以确认文案说清后果的**结构**（哪些会一起消失、不能撤销），
   真实的数字在删完之后回执里给（「已经删掉：话术块 12 条、练习记录 5 条」）。
   **判据 `确认文案里不出现数字` 把这条钉住了** —— 将来有人「顺手」加一个数会先红在那里。
3. **「版本 —」是既有行为**：app target 没有 `CFBundleShortVersionString`，投影里的
   `"—"` 兜底在起作用（它保证版本行不会是空白）。要显示真版本得给 target 补 build setting，
   与本屏的还原无关，记在这里。

## 4. 这条不可逆链路的判据（12 条）

| 规则 | 它挡的是什么 |
|---|---|
| **按下 ≠ 确认** | 按下那一行只把确认摆出来（`.confirming`），不删任何东西 |
| **没走过确认不许开始删** | 相位不是 `.confirming` 时 `.confirmed` 什么都不做 —— 挡的是「确认被漏掉」：视图手滑、或将来有人把「按下」直接接到请求上 |
| **飞行中那一行不可点** | 重复发两次会让幂等回包看起来像「没生效」，于是再点一次 |
| **失败之后可以重试** | 失败不该把那一行卡死 |
| **回执用真实计数说话** | 且**只翻译认得的表名** —— `cascaded` 是 `[String: Int]`，不认得的表不编中文名、也不把表名端到屏幕上 |
| **幂等回包不是错误** | 第二次调用时服务端说 `already_deleted`，屏幕上说「已经不在了」 |
| **确认文案说清不可恢复 ＋ 点名话术块** | 只写「删除素材」会让人以为库里的表达还在 |

变异 **8/8** 咬住。腿 1 955 → **967 tests / 60 suites**。
