# 屏 15 · 登录 / 注册 —— 喂给 OpenDesign 的 brief

- 日期：2026-10-01
- 目标：在**现有稿子** `PRD 转 UI/UX 文档`（14 屏）后面**补一屏**：登录 / 注册
- 上游依据：`fluentwork-meta/docs/40_研发流程与协作/49_FluentWork-account模块Issue草案与排期.md`（A1／A3）
  与稿子 §03 信息架构、屏 12 设置页的账号组、屏 04 的 G4 注册时机

## 一、这一屏要补的是什么

账号链路（A1／A3）已定：**三种登录方式都要，先做账号密码，短信与微信预留**。
所以这一屏要同时回答三件事：

1. 账号密码（邮箱 ＋ 口令）怎么输 —— **注册与登录共用一张表单**
2. 另两种方式的入口**怎么摆**（预留，但不能是「点了没反应」的按钮）
3. 登录之后**本机那些游客记录怎么办** —— 这句话必须在这一屏说清楚

## 二、形态约束（照现有稿子的规矩）

- 它是**全屏页**（稿子 §03：「全屏页（从入口推入）」那一类，与说的房间/回顾/设置同类），
  自带 `app-bar`（`app-icon-btn` 左 ＋ `h1` 标题），**底部不画 tab bar**；
- 沿用现有稿子的 class 与 CSS 变量（`--fw-*`、`set-group`/`set-row`/`app-btn`/`app-card`），
  不要新造一套视觉；
- 屏结构照现有 `<article class="scr">`：`scr-head`（屏号/标题/tagline）＋ `phone-frame` 里的
  `phone-content` ＋ `scr-notes`（说明段）；
- 说明段要写进 06 节「动效与语音状态」之外的**产品判断**（见下）。

## 三、屏内要出现的东西

1. **标题区**：一句话说明「登录后，你的记录才真正属于你」（与屏 04 G4 的措辞同源）；
2. **账号密码表单**：邮箱输入 ＋ 口令输入 ＋ 主按钮（`app-btn primary block`）；
   登录 / 注册两个模式**并列切换**（`seg`），不要两套页面；
3. **短信 / 微信两条入口**：**明确标注未开放**（例如按钮禁用 ＋ 一行小字说明），
   不要做成可点但无反应；
4. **合并说明**：本机已有记录会并进这个账号（措辞要让人不担心丢东西）；
5. **隐私声明**：邮箱属于个人信息，一句「仅用于登录，不用于训练」级别的常驻说明；
6. **错误态**：邮箱或密码不对 —— 文案**只有一句**（服务端有意不区分「邮箱不存在」与
   「口令不对」）；重复注册 —— 「这个邮箱已经注册过了」；
7. **加载态**：提交中按钮禁用 ＋ 明确的进行中文案（不要只有转圈）。

## 四、说明段（`scr-notes`）要写的判断

- **为什么先做账号密码**：三种方式里它不依赖任何外部服务（短信要采购、微信要开放平台审核），
  因而能把「游客 → 注册」这条链路先打通；另两条接进来时只是**多一个凭据校验方式**；
- **为什么两种失败同一句话**：分开报错等于送一个免费的账号枚举器
  （「这个邮箱注册过没有」本身就是不该被随便查的信息）；
- **预留入口为什么是禁用而不是隐藏**：让它可点却无反应，等于教用户「这个产品有坏按钮」；
- **对应**：PRD §六 设置页 · G1/G3/G4 · 49_ A1/A3。

## 五、不在这屏里的

- 第三方登录的完整流程（微信只留入口）；
- 找回密码（做成什么样需要单独定，先不画）；
- 手机号绑定的完整流程（短信未接入）。
