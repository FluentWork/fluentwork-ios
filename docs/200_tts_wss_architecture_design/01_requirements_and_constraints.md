# 需求分析与约束条件

**日期**: 2026-09-21  
**目标**: 明确 iOS TTS WebSocket 系统的功能需求、性能需求与技术约束

---

## 一、功能需求

### F1: 实时语音对话

**用户故事**:
- 用户按住按钮说话 → 实时转写文本 → LLM 生成回复 → TTS 语音播放
- 支持打断：用户可以在 AI 说话时打断并重新提问
- 支持多轮对话：上下文保持

**核心流程**:
```
用户按下 → [开始采集音频]
         ↓
      [上传音频块] → 服务端 ASR → 实时转写文本
         ↓
用户松开 → [停止采集] → 服务端 LLM → 生成回复
         ↓
      [接收音频块] ← 服务端 TTS
         ↓
      [播放音频] → 用户听到回复
```

### F2: 会话管理

**会话生命周期**:
1. **创建会话**: 用户进入页面 → 建立 WebSocket 连接 → 获得 session_id
2. **多轮对话**: 每次对话是一个 turn，由 turn_id 标识
3. **结束会话**: 用户退出 → 关闭 WebSocket → 释放资源

**会话状态**:
- `idle`: 空闲，等待用户输入
- `listening`: 用户正在说话，采集音频
- `thinking`: 用户说完，等待 AI 回复
- `speaking`: AI 正在说话，播放音频
- `error`: 发生错误

### F3: 实时反馈

**用户可见状态**:
- 转写文本实时显示（用户说话时）
- AI 生成文本实时显示（流式输出）
- 音频波形动画（说话和播放时）
- 网络状态指示（连接中、已连接、断开）

**徽章系统** (Badge):
- `user.speech.start`: 用户开始说话
- `user.speech.end`: 用户停止说话
- `ai.thinking.start`: AI 开始思考
- `ai.text.start`: AI 开始输出文本
- `ai.tts.start`: AI 开始播放语音
- `ai.turn.end`: 一轮对话结束

### F4: 错误恢复

**网络错误处理**:
- WebSocket 断线 → 自动重连（指数退避）
- 音频传输失败 → 重试或降级
- 超时处理（无响应 30s → 提示用户）

**降级策略**:
- TTS 失败 → 只显示文本，不播放语音
- ASR 失败 → 提示用户重新说一遍
- LLM 失败 → 播放预设的错误提示音

## 二、性能需求

### P1: 延迟要求

| 指标 | 目标 | 最差可接受 | 测量点 |
|------|------|-----------|--------|
| 首帧延迟 | < 300ms | < 500ms | 用户松开 → 听到第一个音频块 |
| 端到端延迟 | < 1.5s | < 2.5s | 用户松开 → 听到完整回复开始 |
| 音频块间隔 | 20-50ms | 100ms | 相邻音频块播放间隔 |
| 转写延迟 | < 200ms | < 500ms | 说话 → 看到文本 |
| 打断响应 | < 100ms | < 200ms | 用户打断 → 音频停止 |

### P2: 音频质量

| 参数 | 目标值 | 理由 |
|------|--------|------|
| 采样率 | 16kHz | 语音识别标准，平衡质量与带宽 |
| 位深度 | 16-bit | CD 质量，足够清晰 |
| 通道数 | 单声道 | 语音无需立体声 |
| 编码格式 | Opus | 低码率、高质量、开源 |
| 码率 | 16-24 kbps | 语音通话级别 |
| 帧大小 | 20ms | 平衡延迟与效率 |

### P3: 资源占用

| 资源 | 限制 | 理由 |
|------|------|------|
| 内存 | < 50MB | 避免内存警告 |
| CPU | < 20% | 保持流畅，不发热 |
| 电量 | 1 小时对话 < 10% | 长时间使用 |
| 网络流量 | 1 分钟 < 200KB | 节省流量 |

### P4: 可靠性

| 指标 | 目标 | 测量 |
|------|------|------|
| 崩溃率 | < 0.1% | 每 1000 次会话 < 1 次崩溃 |
| 音频丢帧率 | < 1% | 每 100 个音频块 < 1 个丢失 |
| 重连成功率 | > 95% | 断线后 30s 内重连成功 |
| 音频同步误差 | < 50ms | 音频播放与进度条同步 |

## 三、技术约束

### C1: 平台约束

**iOS 版本**:
- 最低支持: iOS 15.0+
- 推荐: iOS 16.0+（更好的 Swift Concurrency）
- 理由: Actor、AsyncStream、AVAudioEngine 改进

**设备支持**:
- iPhone 8 及以上（排除 iPhone 6s/7）
- 理由: 性能要求，Swift Concurrency 优化

**架构**:
- arm64 only（不支持 x86_64 模拟器旧版本）
- 理由: 简化构建，聚焦真机

### C2: 音频约束

**系统限制**:
- AVAudioEngine 延迟: 10-20ms（硬件 + 缓冲）
- AudioSession 中断: 来电、闹钟、其他 App
- 后台限制: 音频播放可后台，录音不可

**最佳实践**:
- 使用 `.playAndRecord` category
- 启用 `.allowBluetooth` 和 `.allowBluetoothA2DP`
- 监听 interruption 通知

### C3: 网络约束

**WebSocket 限制**:
- 需要 TLS/WSS（不支持明文 ws://）
- 移动网络可能有 NAT 超时（60s 无数据 → 断开）
- 弱网场景: 丢包、抖动、高延迟

**应对策略**:
- 30s 心跳保活
- 自动重连（最多 5 次）
- 缓冲区管理（防止内存溢出）

### C4: 并发约束

**Swift Concurrency**:
- Actor 隔离（可变状态必须在 actor 内）
- MainActor（UI 更新必须在主线程）
- 不能从 actor 同步调用外部代码

**音频线程**:
- AVAudioEngine 回调在实时优先级线程
- 不能在音频回调中分配内存、加锁、调用网络
- 必须使用无锁队列传递数据

## 四、依赖与集成

### D1: 第三方库

| 库 | 用途 | 版本 | 许可 |
|---|------|------|------|
| Opus | 音频编解码 | 1.4+ | BSD |
| Starscream | WebSocket（可选） | 4.0+ | Apache 2.0 |
| SwiftProtobuf | 协议序列化（可选） | 1.25+ | Apache 2.0 |

**权衡**:
- **Opus**: 必需，性能和质量最优
- **Starscream**: 可选，URLSessionWebSocketTask 可能足够
- **Protobuf**: 可选，JSON 也可以，但二进制更高效

### D2: 系统框架

| 框架 | 用途 |
|------|------|
| AVFoundation | 音频采集、播放 |
| Foundation | 网络、数据处理 |
| Combine | 响应式数据流（可选） |
| SwiftUI | UI 层 |

### D3: 后端协议

**协议版本**: v1（冻结）

**消息格式**: JSON over WebSocket

**帧结构**:
```json
{
  "type": "user.audio",
  "session_id": "sess_abc123",
  "turn_id": "turn_001",
  "sequence": 42,
  "data": "<base64-encoded-audio>",
  "timestamp": 1726876543
}
```

**核心消息类型**:
- `user.audio`: 用户音频块
- `user.speech.start` / `user.speech.end`: 用户说话边界
- `ai.text.delta`: AI 生成文本（流式）
- `ai.audio`: AI 音频块
- `ai.tts.start` / `ai.tts.end`: AI 语音边界
- `ai.turn.end`: 一轮对话结束
- `error`: 错误消息
- `control.interrupt`: 打断控制

## 五、用户体验需求

### UX1: 响应式设计

**即时反馈**:
- 按下按钮 → 立即显示录音动画（不等网络）
- 收到音频 → 立即播放（不等完整音频）
- 错误发生 → 立即显示提示（不静默失败）

### UX2: 平滑动画

**状态转换**:
- 录音 → 思考 → 播放，流畅过渡
- 音频波形实时动画（60fps）
- 打断时音频淡出（不突兀）

### UX3: 可访问性

**VoiceOver 支持**:
- 所有按钮有语义标签
- 状态变化有语音提示
- 支持动态字体大小

**其他**:
- 支持深色模式
- 支持横屏布局
- 支持 iPad 多任务

## 六、安全与隐私

### S1: 数据安全

**传输安全**:
- 所有通信通过 WSS（TLS 1.2+）
- 证书验证（防止中间人攻击）
- 不缓存敏感音频到磁盘

**隐私保护**:
- 麦克风权限提示清晰
- 音频不在本地存储（除调试模式）
- 遵守 App Tracking Transparency

### S2: 错误处理

**不暴露敏感信息**:
- 错误提示用户友好（不显示技术细节）
- 日志脱敏（不记录用户内容）
- 崩溃报告匿名化
