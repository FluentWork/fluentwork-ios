# FluentWork iOS 语料库本地优先同步策略定案（I13）

**版本**：V1.0  
**日期**：2026-08-30  
**定位**：`I9` 开工前的同步策略定案；定案后才允许动 CorpusStore / SyncEngine 代码  
**上游**：`32` 号 iOS 技术设计 §5、`31` 号后端方案 `phrase_blocks` / cursor 列表、`61` 号难点 3  
**状态**：定案（可实施）

---

## 一、结论摘要

1. **本地只做服务端镜像，不做离线写。** 话术块编辑 / 收藏 / 删除 / `batch-accept` 一律走服务端接口，成功后再回刷本地。
2. **拉取用 `updated_at` 游标增量；软删除用 `deleted_at` 墓碑下发。**
3. **游客 `merge` 成功后：整库失效 → 以新 `user_id` 全量重建。** 禁止把游客缓存“改名”成正式账号残留。
4. **弱网：首屏只读本地；写入进 Outbox 排队，恢复后按序重放，失败可重试且幂等。**

> 本定案对齐 `32` §5.2「本地只做镜像——不做本地离线写」；若未来要支持离线编辑，必须另开 ADR，不得在 `I9` 偷偷放开。

---

## 二、冲突口径

| 场景 | 口径 |
|---|---|
| 服务端字段与本地镜像不一致 | **服务端权威**：增量拉取覆盖本地同 `id` 行 |
| 用户正在看列表时后台刷新到达 | 静默合并；已打开的详情页以进入时快照为准，返回列表后再见新数据 |
| 本地 Outbox 尚有未完成写入 | 禁止用旧镜像覆盖该 `id` 的乐观字段；等写入 ACK 后再拉 |
| 客户端同时点两次收藏 | 以最后一次服务端 ACK 为准；请求带幂等键（见第四节） |

不做：三路合并、CRDT、本地时钟决胜。

---

## 三、游标推进

1. 列表接口遵循后端约定：`GET /corpus/blocks?...&cursor=`（不用 offset）。
2. SyncEngine 持久化两类游标：
   - `list_cursor`：分页浏览用
   - `sync_cursor`：增量同步用，值为上次成功应用的最大 `updated_at`（ISO8601 / 服务端时钟）
3. 增量拉取：`updated_at > sync_cursor`（含软删墓碑行）。
4. 游标只在**整页成功写入 SwiftData 事务提交后**前进；中途失败不前进。
5. 若服务端返回 `cursor_reset=true` 或连续两次增量校验失败：降级为全量重建（同 merge 后流程）。

---

## 四、删除语义

1. 服务端：`DELETE /corpus/blocks/:id` → `deleted_at` 软删除（72h 宽限，见 `31` §3.2）。
2. 增量同步必须下发墓碑：`{id, deleted_at, updated_at}`；本地收到后从可见集合移除，可保留 tombstone 行直至硬删回执。
3. 客户端 UI 删除：先调 API；成功后再改本地。弱网时进 Outbox，UI 可乐观隐藏，但失败要回滚可见性并提示。
4. 素材级联导致的锚点脱敏（`anchor_user_said → "[已删除]"`）按服务端字段覆盖，客户端不本地推断。

---

## 五、收藏状态同步

1. 收藏 / 取消收藏走 `POST /corpus/blocks/:id/favorite`（服务端权威）。
2. 本地 `is_favorite` / `pinned_at` 仅镜像；禁止只改本地不调 API。
3. Outbox 项携带：`block_id`、目标状态、`idempotency_key`（`favorite:{block_id}:{target}:{client_op_id}`）。
4. 重放时若服务端已是目标状态 → 视为成功（幂等）。

---

## 六、游客归并后的本地缓存

1. 触发：`POST /account/merge` 成功（或 AuthFeature 进入 registered 且 merge 完成）。
2. 动作（原子）：
   - 停止 SyncEngine
   - 清空 `CachedBlock` / 相关 Outbox（游客 `user_id` 作用域）
   - 重置 `sync_cursor` / `list_cursor`
   - 以新 `user_id` 全量拉取重建
3. 禁止：把旧游客行的 `user_id` 字段改写成新账号；禁止保留游客 Outbox 到正式账号重放。
4. 归并进行中：语料库页只读占位（loading / “正在迁移语料”），不允许写入。

---

## 七、弱网行为

| 能力 | 行为 |
|---|---|
| 浏览 / 筛选 / 搜索 | **本地优先**；无网也可读缓存 |
| 编辑 / 收藏 / 删除 / batch-accept | 入 Outbox；展示“待同步”；恢复网络后按 FIFO 重放 |
| 同步拉取 | 指数退避；失败不前进游标 |
| 完全无缓存且无网 | 空态 + 重试，不假装有数据 |

Outbox 纪律：

1. 不绕过 SyncEngine 直接写服务端状态（第二波 iOS 禁区）。
2. 单条最多自动重试 N 次（建议 5），其后标记 failed 等用户手动重试。
3. `batch-accept` 整批一个 Outbox 项，服务端幂等键与 `B10` 对齐。

---

## 八、推导出的 `I9` 测试用例（最低集）

1. 有缓存断网：语料库首屏仍可浏览。
2. 断网收藏 → 恢复网络：Outbox 重放成功，镜像与服务端一致。
3. 增量含软删墓碑：本地可见列表移除对应块。
4. merge 后：旧游客缓存不可见，新账号全量重建成功。
5. 游标事务失败：游标不前进，重拉不丢不重（允许短暂重复，最终一致）。

---

## 九、与 `B10` 的核对清单

`I9` 动码前 / `B10` 落地后核对：

1. 列表是否 cursor 制，且增量能带回 `deleted_at` 墓碑
2. `batch-accept` 幂等键契约
3. favorite 接口请求/响应字段
4. merge 后 `phrase_blocks.user_id` 迁移是否完成（服务端）

若核对冲突：回写 `meta`，不在本仓私下改口径。

## 十、Out of Scope

1. 离线编辑正文 / 离线新建块
2. 多设备实时协同
3. 收藏以外的完整置顶交互细化（第二波只接线最小收藏）
4. 闪测调度字段的客户端写入
