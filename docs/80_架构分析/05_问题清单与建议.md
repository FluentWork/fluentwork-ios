# 05 — 问题清单与建议

> 基线 `2aa8795`。本文件是 `01`–`04` 的收敛：**不引入新结论**，只把四章里已经带证据的条目排成一张可执行的表。
> 每条都指向原章的行号，可当场复核。

## 0. 这份清单怎么读

**分级只按一件事**：不做会怎样。

| 级 | 含义 | 判据 |
|---|---|---|
| **S0** | 不做就继续带着已知风险跑 | 已在真机出过事故，或需要一个只有人能给的决定 |
| **S1** | 不做会在下一次同类缺陷上再花一遍时间 | 结构上「看起来被守住了，实际上没有东西会红」 |
| **S2** | 不做只是让下一个人多读一会儿 | 重复、命名、注释、死代码 |

**「需决策」列**是这份清单的重点。S1/S2 我可以直接做；S0 里的每一条都卡在一个本仓无法单独回答的问题上。

**确定性沿用系列约定**：【实测】有命令输出；【读码】从源码读出；【推断】可能另有解释。

## 2. S1 — 结构上该补的「防线」

共同形状：**判据存在，但没有任何东西会因为它失效而变红。**

| # | 条目 | 动作 | 风险 | 价值 | 证据 |
|---|---|---|---|---|---|
| S1-1 | `pcmBuffer` / `isCapturingSpeech` 跨会话存活，安全性依赖 `removeAll()` 的调用顺序 | 收进类型，**或**加一条「跨会话不清空必须红」的测试 | 低 | **高** | `03` §4.4 |
| S1-2 | 11 份等待助手（`waitUntil` ×8 + `waitForPhase` ×2 + `waitForProcessingStage` ×1）+ 8 份错误类型，已漂移 5 类 | 抽成一份测试支撑 | 低 | **高** | `04` §3.1 |
| S1-3 | 超时值的理由只有一份副本（`SpeechSessionMiddlewareTests.swift:2155-2168`），而 `SpeakingRoomSessionWiringTests` 还有 65 处 1 秒 | 把那段注释提成共享，再据此重定 | 低 | **高** | `04` §3.2 |
| S1-4 | `audioEventPump`（上行，209 行）未纳入路由表（D9） | 抽成路由表，复用 `20_` 的手法 | **低**（只搬路由） | 中 | `03` §4.3 |
| S1-5 | 无端到端测试：`Integration/` 只有 51 行 | 补一条进程内真 socket → 中间件 → store | 中 | **高** | `04` §3.3 |

| S1-7 | D8：音频路径每帧两次 actor 跳转，而 `TransportEventRouter` 自己的注释反对其中一次 | **先量基线**，再决定是否合并 | 中 | 中 | `03` §4.2 |

**S1-1 是本清单里最像「定时炸弹」的一条**：它不是性能也不是风格，是**一个没有测试保护的不变量**。`03` §4.4 的结论是——如果哪天有人调整了 `removeAll()` 的顺序，**没有任何测试会红**。

**S1-3 的形状值得记住**：2026-09-12 那节课（1 秒超时不是延迟断言）在一个文件里被认真学到了、写下了理由、点名了两次 CI 失败——然后**没有传到那个有 65 处同类调用的文件**。这不是「没人想过」，是「想过的地方和要用的地方不是同一个地方」。

**S1-7 排在 S1 而不是 S0**：因为 `03` §4.2 的结论是**先测量再改**。没有延迟基线就合并跳转，是拿一个未知换另一个未知。

## 4. 反过来：这些看起来是问题，但**不要改**

写下来是为了防止下一个人（包括我）把它们当缺陷修掉。

| 看起来像 | 实际是 | 证据 |
|---|---|---|
| `TransportEventRouter` 是 `struct` 而不是 `actor`，要自己保证串行 | **刻意**。`actor` 在这里只提供调用方已保证的串行性，代价是每帧一次额外跳转 | `TransportEventRouter.swift:18-24` |
| 未知控制帧不回错误，只忽略 + 计数 | **与后端对称**，两侧都写了理由 | `URLSessionSocketTransport.swift:316-332` vs 后端 `handler_control.go:465-486` |
| `ai.audio.chunk` 收了但什么都不做 | **后端没有生产者**（`voiceproto/frames.go:21` 是唯一出现处）。只留痕，不播放 | `70_/20_` §2.2 |
| 丢弃埋点一轮只报一次 | 刻意。去重键是 (轮次, 原因)；改成 `markTurnOnce` 会给事件名加 `timing_` 前缀，**让真机核对表失效** | `70_/21_` §3.3–3.4 |
| `Tests/` 下只有 `FluentWorkCoreTests` 一个 target | 测试都在它下面按目录分；`UI/`、`Integration/` 是它的子目录 | `04` §1 |

## 5. 如果只做三件事

按「不做会怎样」排序，我选这三条：

1. **S0-1（Stage 3）** —— 唯一一条同时关掉 D7 与 D2 的改动，且本仓已经为它铺好了路。
2. **S1-1（`pcmBuffer` 的不变量）** —— 一个没有测试保护的不变量，且它在**音频路径**上（`AGENTS.md` High-Risk Path #1）。加测试的成本极低。
3. **S1-2 + S1-3（测试助手与超时理由）** —— 两条合起来是一次改动：把漂移的 11 份助手收敛成一份，同时让那段超时论证只有一个副本。这是本系列**最具体**的发现。

不选 S1-5（端到端测试）不是因为不重要，是因为它成本最高，且 S0-3 的真机验证能覆盖它的一部分价值。
