# 20 — 实现说明：已知但无人接的控制帧必须留痕

> 对应缺陷：`10_事实基线与缺陷清单.md` **D11**（🟡【读码】）。
> 改动：给 `.aiAudioChunk` 注册一个**只上报**的 handler；把「无人接」的名单从 13 类收成 12 类，并**逐条写明理由**。
> 红：`audioChunkControlFrameLeavesATrace`（`TransportRoutingEquivalenceTests.swift:202`）。

## 1. 这条改动守的是什么契约

**一类帧「已知、但没人接」必须留下痕迹，而不是安静地消失。**

改动前的形状：`ai.audio.chunk` 解码成功 → 落 `fallbackHandler` → `SocketTransportEventMapper` 对 `.control` 返回 `nil` → 什么都不发生。

同一个仓库里、同一个高度上，有另一个方向相反的对照：

| 情形 | 走到哪 | 留下什么 |
|---|---|---|
| **未知** type（如 `ai.tts.audio`） | 解码抛 `.unknownType` → 传输层 `emit(.diagnostic(.unsupportedControlFrame(...)))` | `transport_control_frame_ignored` |
| **已知、但没人接**（`ai.audio.chunk`） | 解码成功 → fallback → mapper 返回 `nil` | **一条都没有** |

`unsupportedControlFrame` 诊断只对**未知** type 触发（`URLSessionSocketTransport.swift:329-332`），所以「已知但没人接」是**唯一无声的一类**——而它恰好是「音频」那一类。

## 2. 为什么这是缺陷

### 2.1 静默的方向是反的

未知 type 被记下来，理由写在传输层那段注释里：那是「服务器比我们新」，值得知道。

但真正让用户有感知的是另一种：**服务器换了一种我们认识、却从未实现的形状**。这时没有「我们落后了」的报错，只有「AI 不说话」。

`ai.audio.chunk` 正是这个形状——它宣告音频（`{"type":"ai.audio.chunk","sequence":N}`）。若网关改用它而不是二进制帧，客户端会：收到一串控制帧、什么都不播、**日志里空无一物**。

### 2.2 但它的风险不是活的——这一点必须写清楚

**后端没有生产者。** 逐条读到的（全部在 `fluentwork-backend` 仓内）：

| 证据 | 位置 | 内容 |
|---|---|---|
| 常量声明 | `internal/voiceproto/frames.go:21` | `TypeAIAudioChunk = "ai.audio.chunk"` |
| 全仓代码引用 | 同仓 `grep -rn` | **只有这一处**，无第二处 |
| 冻结断言 | `internal/voiceproto/frames_test.go:445-447` | 「no producer, no consumer, no test, **on either side of the wire**」 |
| 实现说明 | `docs/archive/implementation-details/58_...md:13` | 「后端只有一个常量声明（`frames.go:21`），**全仓再无一处引用** —— 连测试都没有」 |
| 设计决策 | `docs/30_技术方案/51_WSS_V2_帧协议设计_2026-09-08.md:169` | `\| ai.audio.chunk \| ❌ 不加 \| 用 turn_id + seq 已足够 \|` |

所以本次**不是**「补上音频处理」。补播放等于给一条不存在的路修路：帧上没有 payload 字段（解码只读 `sequence`），后端也不发它。

要补的是**可见性**——这条帧一旦真的来了，日志里必须有东西能指认它。

### 2.3 为什么不做成「会话失败」

另一个可选方案是：收到 `ai.audio.chunk` 就 `.failed(...)`，像 `.error` 那样。**没有采用**，两个理由：

1. 它是**产品决策**，不是实现决策——「收到一个我们不播的音频通知」要不要打断用户正在进行的练习？本仓没有依据，不该由实现替产品定。
2. 它与 `.error` 性质不同：`.error` 是网关**明确宣告出了事**（`code` 是稳定机器码，专为分支设计）；`ai.audio.chunk` 只是一个我们不认识的**正常**帧。把它升级成致命错误，会把「服务器多发了点什么」变成「会话断掉」——正是 `URLSessionSocketTransport` 那段注释在未知 type 上已经拒绝过一次的取舍。

## 3. 改法

| 位置 | 改动 |
|---|---|
| `SpeechSessionMiddleware.swift:815-826` | 注册 `controlHandlers[.aiAudioChunk]`，只 track `tts_audio_chunk_ignored` |
| `SpeechSessionMiddleware.swift:990-996` | 计数注释 13 类 → 12 类，并指向带理由的名单 |
| `TransportRoutingEquivalenceTests.swift:21-30` | `ownedTypes` 六个 → 七个（加 `.aiAudioChunk`） |
| `TransportRoutingEquivalenceTests.swift:227-270` | `unownedControlFramesChangeNothing` 改成带理由的分组名单 + 集合相等断言 |

### 3.1 埋点为什么用新名字，而不是复用 `transport_control_frame_ignored`

`transport_control_frame_ignored` 现在的含义是「**我们落后了**」。复用会把两个方向相反的事实混进同一个查询：一个是「服务器比我们新」，一个是「服务器用了一种我们从没实现的形状」。

后者的诊断价值更高——它对应的是「用户听不到声音」，而不是「某个新功能暂时不生效」。混进去就找不到了。所以新名字 `tts_audio_chunk_ignored`，与 `tts_frame_dropped` / `tts_decoder_failed` 同一个家族。

属性用 `frame.wireType.rawValue` 而**不是**字面量 `"ai.audio.chunk"`：字面量会和枚举漂移，而 `wireType` 是穷尽 switch（`WSControlFrame.swift:174-196`），加 case 会编译失败。

### 3.2 有意**不做**的两件事

1. **不把这类帧计进 `ttsTrace.audioFrameCount()`。** 那个计数是 `ai.tts.end` 的 `audio_frames` 属性，用来回答「这一轮到底喂了几帧给解码器」——诊断静音时的关键数字。把「没播的通知帧」混进去会污染它。
2. **不动 `SocketTransportEventMapper`。** 它是 `.control → 动作` 的映射，而 `.aiAudioChunk` 的正确映射**就是没有动作**。把「上报」塞进 mapper 会把它从纯映射变成有副作用的东西，也就破坏了 `errorFrameStillTearsTheSessionDown` 那类测试所依赖的「映射可单独断言」性质。

## 4. 顺带把「没人接」的名单变成「逐条写明理由的名单」

这是本次更值得留下的部分。

改动前，`unownedControlFramesChangeNothing` 的名单是一串类型，**没有理由**。一张「没人接」的名单如果不写理由，下一个人分不清某一项是**有意忽略**还是**漏了**。

D11 就是这样：`ai.audio.chunk` 在这张名单里待过，而没人说得清它为什么在这。**名单本身没错，错在它没有可判读的内容。**

改动后，每一项带一句理由，分四组：

| 组 | 类型 | 理由 |
|---|---|---|
| 只上行 | `auth`、`session.start`、`user.speech.start`、`user.speech.end`、`client.turn.abort`、`interrupt`、`ping` | 客户端 → 网关，这一侧收不到（`ping` 的回包是 `pong`） |
| 传输层已消费 | `pong` | `recordClockOffsetIfPong` 先拿它算时钟偏移，再原样 emit |
| 网关应答 | `session.ready`、`session.end` | 收到即无需动作：`session.ready` 的 `session_id` 客户端本来就有；`session.end` 是客户端自己发的那个帧的回执（后端 `handler_control.go:443`），会话在本地已经拆掉 |
| 死面 | `handshake` | `connect` 发的是 `auth`（`URLSessionSocketTransport.swift:116-118`），后端也没有这个常量；只有测试在造它 |

并加一条**集合相等**断言：

```swift
let classified = Set(unowned.map(\.frame.wireType)).union([.error])
let unownedByTable = Set(WSControlFrameType.allCases)
    .subtracting(Set(TransportRoutingEquivalenceTests.ownedTypes))
#expect(classified == unownedByTable, "有控制帧既没有 handler、也不在这张带理由的名单里：…")
```

于是**新增一类 `WSControlFrame` 会让这条红**——要么给它注册 handler，要么在名单里补一条带理由的。分类不再靠纪律维持。

> 这也是本次唯一想留下的形状：**「没人接」要能被判读**。同族的形状在本轮别处出现过——`16_`/`17_` 的「一个从不取真值的判据」、`19_` §6.3 的「判据被复制进替身」。三者都是「看起来有保护、实际没有」。

## 5. 影响面

- **状态机**：无影响。
- **协议（线上）**：无影响。不新增发送、不新增接收。
- **音频**：**行为零变化**。`.aiAudioChunk` 的到达**仍然不播**，只是多一条日志。
- **可观测性**：**新增** `tts_audio_chunk_ignored`（`type`、`sequence`）。这是本次唯一的运行时行为变化。
- **回滚**：`git revert` 该提交即可。

### 6.3 为什么需要给 `makeProductionRouter` 加一个 `tracker` 参数

它原来只返回 `recorder`（dispatch 记录）。而 `.aiAudioChunk` 的痕迹**不在 dispatch 里**——它不产生动作。一条只看 `recorder.actions` 的测试对 D11 是瞎的。

所以工厂加一个可传的 `CapturingTracker`，默认仍是新的空实例，既有调用点不受影响。这与 `19_` §6.2 的判断同源：**观察点要落在被改的那条链路上**，不能落在它旁边。

## 7. 顺带发现：`handshake` 是一个 iOS 侧的死面，且 `10_` §2 的方向列有两格是错的

写理由表时查出来的。**代码不修**，但表改了、依据留在表下。

### 7.1 `handshake`

`WSControlFrame.handshake` 在 `Shared/` 里**从未被构造**。`URLSessionSocketTransport.connect` 发的是 `auth`（`:116-118`，注释原文「backend expects "auth" type, not "handshake"」），后端 `voiceproto/frames.go` 的常量表里**没有** `handshake`。只有测试在造它（`SocketTransportTests.swift:9`、`TransportRoutingEquivalenceTests.swift:38`）。

它与 `ai.audio.chunk` 是同一类东西——**一个冻结的死面**——只是方向相反：那个是后端有常量没生产者，这个是客户端有 case 没构造点。

**代码不修的理由**：删一个枚举 case 会牵动 `CodingKeys`、`wireType` 的穷尽 switch 与 `controlFrameCodecRoundTripsKnownTypes`，属于独立的一条；而它比 `ai.audio.chunk` 更无害——没有语义，收到也无事可做（理由表里已经写明）。

### 7.2 为什么连表一起改了

`10_` §2 把 `handshake` 的方向记成 **S→C**、把 `ping`/`pong` 记成 **双向**。两格都不对：

- `ping` 是 C→S（`DefaultSpeechSessionClient.swift:128` 发），`pong` 是 S→C（网关在 `handler_control.go:201-212` 回）——**各占一向，不是双向**。

这张表是「读码即得」的事实基线，**读错一格不会让任何测试变红**。所以只改对的那一格、不留下核对依据，下一个人没有理由相信它比原来那版更对。改法是：两格划掉改对，并在表下写明来路。

**这也是本次想留下的第二个形状**：事实基线里的错，不会自己浮出来——它只能靠"用它的那一刻"暴露。`handshake` 这一格就是被理由表逼出来的：要给「它为什么可以是安静的」写一句真话，就必须先确认它到底在哪个方向。

### 7.3 有意没做的第三件事

**没有把 `10_` §2 剩下的 16 格逐格重核。** 那需要把每一格都追到生产构造点，属于独立的一条（而且大概率还会翻出几格）。本次只改「写理由时顺手撞见的两格」，并在表下声明了范围。
