# 09 — 麦克风替身（`FW_MOCK_MIC`）

> 真机验证音频链路时，别用真麦克风喂链路。用这个替身。
> 代码：`Shared/FluentWorkCore/Audio/MockAudioEngine.swift`（**仅 DEBUG**）。

## 1. 为什么

用真人开口喂链路，每次验证都要有人说话、每句都不一样、VAD 的收尾时刻还依赖环境
噪声 —— 而我们要验的是**音频回来之后的那半条链路**（轮次归属、解码、播放、打断），
不是麦克风。替身把「说一句」变成一个确定性的动作。

**它不是 `swift test` 里的那道 mock**：那些 mock 只活在测试进程里；这个替身活在
真机上，跑的是完整的 app + 真实 WSS + 真实播放器。

## 2. 怎么开

Xcode → Product → Scheme → Edit Scheme → Run → Arguments → Environment Variables：

```
FW_MOCK_MIC=1                 # 打开替身
FW_MOCK_MIC_UTTERANCE_MS=1500 # 这一句持续多久（默认 1500ms）
FW_MOCK_MIC_AUTO_MS=4000      # 可选：无人值守，每 4 秒自动说一句
```

**UI 不用改**：默认的 tap-to-start，一次点击 = 一轮。点「开始说话」后替身发
`speechStarted` → 每 20ms 一块 16kHz PCM16（1kHz 正弦，与 dev-echo 的 fixture 同一种音频）
→ 到时长后 `speechEnded`，不需要 VAD、也不需要人说第二句话。

## 3. 替身接管了哪三处

麦克风在客户端有三个入口，只替一个是不够的（漏掉权限那处，验证时照样弹框、
系统状态栏照样显示在用麦）：

| 入口 | 生产 | 替身开着 |
|---|---|---|
| 引擎采集（`LiveAudioEngine` + `installTap`） | 真麦克风 | 脚本化的 PCM，**不开麦** |
| UI 权限（`SpeakingRoomView` → `MicrophonePermission.request()`） | 弹系统权限框 | 直接返回 true，**不弹框** |
| 音频会话（`AudioSessionManaging`） | `.playAndRecord` + `.voiceChat` | `.playback`，**麦克风不亮** |

**播放不替**：`playback` 持有的就是生产用的 `LiveAudioEngine`，播放与打断全部转发给它。
「能不能出声」是这条链路上唯一只能靠耳朵裁决的判据（单测看不到静音），把播放也替掉
等于把这条判据一起丢掉。所以 TTS 该响还是会响。

## 4. 日志里怎么认出来

- `transport_audio...` / `tts_*` 照常出现（链路是真的）
- **多一行**：`timing_audio_voice_processing {"detail": "mock mic: on, no capture graph"}` ——
  看到它才说明麦克风确实被接管了；没有它，说明 `FW_MOCK_MIC` 没生效（检查 scheme 的环境变量）
- **不再有**麦克风权限弹框、状态栏不再有麦克风指示

## 5. 它替不掉的东西（别被它骗了）

- **VAD 本身**：`.tapToStart` 的收尾在生产上由 VAD 判，替身是按脚本收尾的。
  要验 VAD 阈值/收尾时长，只能用真麦克风。
- **回声消除（AEC）**：`voiceProcessing` 那个开关的真实效果只有真麦+外放才验得出，
  替身只发一行「mock mic」的日志说明它没走采集图。
- **蓝牙/路由切换**：`reconfigureForRouteChange` 转发给真引擎，但没有真实路由事件。

## 6. 契约（`MockAudioEngineTests`，8 条）

- 一次点击 = 恰好一轮：`speechStarted` → 3 块 640 字节 PCM → `speechEnded`
- 手动收尾 + 脚本跑完不会发两次 `speechEnded`
- `discardActiveSpeech` 丢句但**不发** `speechEnded`（发了会给网关送一个没有音频的轮次）
- 采集开始只配播放会话（不配 `.playAndRecord`）
- 默认关闭：没设 `FW_MOCK_MIC` 时替身不生效
