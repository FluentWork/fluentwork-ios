## 3. 改法：一张表，加两处顺序约束

新增测试驱动全部 11 个事件，然后按表断言「埋点名存在 + 属性键存在」：

```swift
let expected: [(name: String, keys: Set<String>)] = [
    ("timing_vad_speech_start", []),
    ("timing_audio_uplink_turn", ["forwarded", "dropped_outside"]),
    ("timing_audio_capture_armed", ["was_running", "start_attempted", "start_threw", "running"]),
    …
]
for (name, keys) in expected {
    let hit = try #require(tracker.events.first { $0.name == name },
                           "埋点 \(name) 不见了——它是真机验证要读的行之一（`70_/08_` §3 尚未做）")
    for key in keys {
        #expect(hit.properties[key] != nil,
                "埋点 \(name) 少了属性键 \(key)——它降级成了一条无法判读的日志")
    }
}
```

**属性键只断言「存在」不断言「值」**：值由各条自己的行为测试负责，这张表管的是「这行还读得懂吗」。两者不重叠，所以不会因为行为改动而误红。

### 3.1 两处顺序约束（都是被真实约束逼出来的）

1. **`.speechEnded` 必须排在 `.speechStarted` 之后**——它开头是 `guard speechCaptureGate.isOpen else { continue }`，闸门没开就不发埋点。
2. **`.failed` 排在最后**，并且它**兼作屏障**：泵是逐条串行处理事件的，所以等到 `timing_audio_engine_failed` 出现，前面 10 条必然都已处理完。这让测试只需要等**一个**条件，而不是等 11 个（也就少了一处 flaky 面）。

## 4. 为什么只改测试就够

因为**缺的不是行为，是断言**。生产代码已经正确地发了这 11 条埋点——问题只是「没有任何东西会因为它不发了而变红」。

所以本条的处置是**加断言**，而不是改代码。这也让它的风险为零：生产代码一行未动（`git diff --stat Shared/` 为空，已核），不存在回归可能。

## 6. 测试

### 6.1 为什么没有「先红」（`AGENTS.md` 例外条款）

`AGENTS.md` 要求「每个修复都从一条会失败的测试开始」，三条例外之第一条是「新能力（不存在失败态）——改为钉住期望行为」。

本条适用：钉的是**既有的**可读性，改动前后生产行为完全相同（因为生产代码没改）。所以**没有可失败的状态**，测试第一次跑就是绿的。

### 6.2 但「钉住的测试」有它自己的失效模式：它可能根本不会咬

**一条永远绿的守卫比没有守卫更糟**——它会让下一个人以为这件事被管住了。所以本条的验证方式不是「先红」，而是**两次变异验证**：故意在生产代码里制造它该抓的两种破坏，确认它变红。

**变异一：改掉一个埋点名**（`audio_capture_armed` → `audio_capture_armed_MUTATION`）

```
✘ Test captureDiagnosticsKeepTheirMarkNamesAndPropertyKeys() recorded an issue at SpeakingRoomSessionWiringTests.swift:563:23: Expectation failed: tracker.events.first { $0.name == name }
↳ 埋点 timing_audio_capture_armed 不见了——它是真机验证要读的行之一（`70_/08_` §3 尚未做）
↳ tracker.events.first { $0.name == name } → nil
```

**变异二：删掉一个属性键**（`captureArmed` 的 `"running"`）

```
✘ Test captureDiagnosticsKeepTheirMarkNamesAndPropertyKeys() recorded an issue at SpeakingRoomSessionWiringTests.swift:568:13: Expectation failed: hit.properties[key] != nil
↳ 埋点 timing_audio_capture_armed 少了属性键 running——它降级成了一条无法判读的日志
↳ hit.properties[key] → nil
```

**两次都咬住了，而且失败信息指名道姓**（哪条埋点、缺哪个键）——这正是这张表存在的意义。两次变异均已还原，`git diff --stat Shared/` 为空。

> **这是本条的真正交付物**：不是「加了一条测试」，而是「**证明了这条测试会咬**」。任何「钉住既有行为」的票都应当这样做——否则它只是在增加测试数量。
